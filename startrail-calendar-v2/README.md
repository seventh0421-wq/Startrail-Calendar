# 星旅日誌 Startrail Calendar — V2.3.0｜記事與生日紀念日

專為 10 人以內 FF14 好友設計的共用行事曆：星空冒險風、手機優先、Google 登入與受邀會員權限、自由開團、+1／候補／坦補打職業志願／主揪排位，與 Discord 莫古力自動公告、綁定帳號、直接 +1。

**這份檔案尚未部署到你的 GitHub／Vercel；程式測試通過不代表已實測真實 Firebase／Discord。**

## V2.3.0 新功能：📌 記事

建立日程時選 **📌 記事**，可選：

- **🎂 生日**、**💗 紀念日**、**📌 一般記事**。
- 記事只需 **標題、日期**，可填備註；沒有開始／結束時間、集合地點、人數、+1、候補、職業分配。
- 支援 **只記錄一次**、**每年重複**。生日／紀念日預設每年重複，一般記事預設單次；都能自行修改。
- 例如「小花生日」2026/11/07，若每年重複，2027/11/07、2028/11/07 會自動出現在月曆。**不需要輸入朋友真實出生年份**；日期中的年份只是第一次顯示的年份。
- 閏年 2/29 的記事僅在閏年顯示，沒有偷偷改成 2/28。
- 首頁新增「近期記事與紀念日」，月曆新增粉色📌分類篩選；一般活動不受影響。
- **記事不會傳到 Discord 揪團公告頻道**，也不會出現報名按鈕。要加入提醒通知，後續需另外設計並取得好友同意。
- 建立者或管理員可以編輯或移除記事。「移除」是將狀態標記已取消（不直接刪除 Firestore 資料）。
- 已發布的普通活動與記事不能互相轉換，避免破壞既有報名；需要時另建一筆。

**隱私提醒**：這是共享行事曆，所有受邀成員都看得到記事。替朋友新增生日或其他私人紀念日之前，請先徵得當事人同意；不要在備註記錄敏感個資。

## V2.3 更新部署步驟（從 V2.2 升級）

1. 使用 `startrail_calendar_v2_3_notes_patch.zip` 的檔案，按照相同相對路徑覆蓋 GitHub 現有 `startrail-calendar-v2` 目錄。
2. GitHub Commit 後，等 Vercel 自動重新部署，確認 Deployments 狀態為 **Ready**。
3. **不必**重新設定 Firebase、Discord Bot Token、公開金鑰或 Vercel 環境變數，也不需要清空資料庫。
4. 登入網站 → **新增** → 選 **📌 記事** → 標題例如「小花生日」 → 選日期 → 選「🎂 生日」＋「每年重複」 → 新增日程。
5. 在月曆選「📌 記事」篩選，切換到下一年的相同月份，確認生日會再出現；點進去不應有 +1。Discord 公告頻道也不應新增一則揪團公告。
6. 再新增一場普通活動測試開團與 +1；確認原本的 Discord 公告、職業志願和排位功能仍正常。

## 技術備註

- 記事繼續儲存在 `events` Firestore collection，`category: 'note'`，無須變更 Firestore Rules。`allDay:true`；年度重複由前端產生虛擬顯示，不會每年複製一份資料。
- API 查詢最近 250 筆活動，另外依單欄位 `category=='note'` 讀取最多 100 筆記事，避免很久前建立的生日在多年後消失。這是小型好友群的設計；若將來記超過 100 筆，須增加分頁或獨立記事集合。
- 非編輯中、頁面可見時，每 2 分鐘自動更新；手動開團／+1 等操作仍會立即同步，切回視窗也會更新。這樣可降低免費 Firestore 讀取量。
- 目前不會在生日到來時發自動 Discord 提醒；未來可以增加明確的開關，並考慮朋友的隱私意願。
- 此版本延續 V2.2 的 Google／Discord 一次性綁定碼與互動端點，原本設定保持不變。

## 本地測試

Node.js 22 以上：

```bash
npm install
npm run check
npm test
# 如果你有完整的 Firebase .env.local，才需要下面的本機伺服器：
node --env-file=.env.local server.mjs
```

**安全**：`FIREBASE_SERVICE_ACCOUNT_JSON` 與 `DISCORD_BOT_TOKEN` 永遠不可放入 public 目錄、Commit 到 GitHub 或貼到聊天室。保留現有 Vercel Production 的環境變數即可。
